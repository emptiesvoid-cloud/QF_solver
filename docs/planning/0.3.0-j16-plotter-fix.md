# QF Solver 0.3.0 — J16 correction ciblée du traceur harmonique

## Périmètre

Cette contribution est basée directement sur `main` au commit
`be455745f4a1c2cf81cb9448830223107dc39b66`. Le pilote de résonance J15
n'existait pas sur cette base; il est ajouté comme dépendance nécessaire
au correctif. Les fichiers solver importés par ce pilote ne diffèrent pas
de `main` au SHA relevé.

La source exacte de la tentative historique est le commit complet
`591e04fcd648c7969ead41c13a9c80855e6623f1`; son SHA-256 de fichier est
`71e06e7cf3d908c3615b155358ce2752f0ef4c86722d0e80b463dac694ffd781`.
Cette exécution reste `PYTEST_FAILED` et ses 152 statuts
`QF_GUARD_REJECTED` ne sont pas modifiés.

## Cause et correction

Le producteur construisait les lignes de référence avec les clés
`navier_uz_amplitude_mm` et `navier_uz_phase_degrees`, alors que
`_plot_response` consommait `reference_uz_amplitude_mm` et
`reference_uz_phase_degrees`. La `KeyError` se produisait après la
sérialisation des checkpoints.

Le producteur et le traceur partagent maintenant le schéma `reference_*`.
Le traceur valide les champs et les fréquences appariées avec des erreurs
explicites; il marque les points rejetés sur les panneaux amplitude et
phase, sans réécrire les statuts ni muter les lignes.

## Vérifications

Quatre tests unitaires ciblés vérifient le tracé avec des champs valides,
le champ manquant, l'alignement des fréquences, le marquage des points
rejetés et la conservation des entrées/statuts. Le replay lit un fichier
`site_data.json` fourni et n'appelle aucun solveur. Ce correctif ne contient
pas de nouvelle preuve FEM.

Les sources solver requises sont présentes sur `main`; le seul outil
absent de cette base est le runner local `development_autonomous.py`, qui
n'est pas requis pour ces tests unitaires.
