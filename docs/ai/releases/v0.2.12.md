## How to interpret this inventory

The columns below deliberately distinguish four claims:

- **In code / interface:** implementation, route, API symbol, CLI command, or data format is present in the inspected candidate.
- **Recorded evidence:** a test, verification run, external comparison, or campaign is named by a release record. Its result remains bound to the identity and environment in that record.
- **Current-HEAD evidence:** this documentation update ran no solver, FEM calculation, benchmark, or scientific test. No new current-HEAD numerical PASS is claimed.
- **Maturity/disposition:** the exact recorded package or capability decision. A closed WP is not automatically a generally qualified feature, and a code path or test PASS does not promote maturity.

The [API reference](../../reference/qf_solver_api.md) is marked controlled_candidate and contains the exact export inventory, signatures, and STABLE/PROVISIONAL categories. The [compatibility descriptors](../../../src/solveur/compatibility/descriptors.py) describe route declarations, not scientific maturity. The older [cumulative capability index](../../capabilities/index.md) is a controlled-candidate document for the published v0.2.11 surface and does not replace this release-specific inventory.

## Full public API and CLI surface

The public API includes more than solving:

- **Stable core workflow:** model construction, JSON load/save, mesh validation and audit, method listing, model solve, error/result types, result assessment, and safe result save/export.
- **Provisional input/output and post-processing:** bounded INP reader, HDF5 mixed results, solid/harmonic/modal-transient stress recovery, and their route-specific schemas.
- **V&V operations:** benchmark and demonstration catalogs, benchmark execution, V&V study import/run/compare, linear-solver/contact/MITC4 verification, structured TET4 convergence studies, qualification readiness, release-V&V artifact generation, manifest campaign entry points, and evidence bundle save/verify.
- **Large-model operations:** convert/load/inspect/solve large TET4 models, load distributed partitions, generate blocks/cantilevers, readiness and environment reports, chunked post-processing, large qualification/benchmark campaigns, PETSc profile/tuning reports and scaling analysis.

The CLI exposes corresponding commands, including solve/check/inspect/evidence/import-mesh; benchmark and V&V; large-model generation, conversion, solving, post-processing, readiness, and analysis; contact/element verification; evidence/qualification operations; and method listing. Exact function signatures, export stability, return types, command flags and exceptions are maintained in [qf_solver_api.md](../../reference/qf_solver_api.md), [API stability](../../reference/api_stability.md), [interfaces](../../reference/interfaces.md), and [the CLI parser](../../../src/solveur/cli/main.py).
