# Security Policy

## Supported Versions

| Version or channel | Security support |
| --- | --- |
| Latest published release | Best-effort security support. |
| Current `0.2.8` pre-publication candidate | Security fixes may be accepted during release preparation; it is not a published release. |
| Older releases | Best effort only; not actively supported. |

Support is provided on a best-effort basis. A security fix for the current
candidate does not imply that the candidate has been released, certified or
qualified for a broader technical scope.

Current candidate publication status: `NOT_PUBLISHED_YET`. DOI status:
`NOT_AVAILABLE_YET`.

## Reporting

Do not publish a suspected vulnerability, arbitrary file write, unsafe command
execution path, corrupted-result issue or evidence-integrity defect in a public
issue before a maintainer has assessed it. Use GitHub private vulnerability
reporting when it is enabled for the repository. Until then, contact the
repository owner privately through the GitHub profile.

Include a minimal reproduction, platform, Python version and impact. Do not
attach restricted industrial models or confidential result files.
